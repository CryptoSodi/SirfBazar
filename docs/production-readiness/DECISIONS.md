# Readiness Decisions And Open Policies

Phase 0 conclusions/proposals only. Date: 2026-10-08. Owners have not approved new implementation or operational configuration.

| Decision | Status | Rationale / trigger / owner requirement |
| --- | --- | --- |
| One backend, existing eight apps | VERIFIED as inventory, source reviewed R/L | Extend existing apps/api; no replacement backend/mobile/web redesign. Readiness of each remains PARTIAL. |
| Guest-first public browsing | PARTIAL implementation, preserve | Catalogue and location routes are Public; guest session created for cart activity, not a requirement for viewing products. Keep checkout sign-in and explicit quote approval. Do not “fix” 401 by making private carts/orders public. |
| Which source is authoritative | PARTIAL | R is detailed audit target and selected production branch; L is older checkout. Git proves R API source matches historical deployed commit, not current service state. No branch switching/promotion in Phase 0. |
| Production mocks | PARTIAL | OTP/delivery mock guards exist; Google production mode is unsafe. Recommend reject mock/unknown Google or disable only that provider pending configuration. No provider activation/credential rotation by this audit. |
| Strong privileged authentication | MISSING in traced password route | Admin password bcrypt exists, but no MFA/step-up/business-action reconfirmation or route abuse budget traced. Owner defines pilot policy and break-glass access; don't replace role checks with frontend hiding. |
| Native credential storage | PARTIAL | Customer SecureStore migration exists; add merchant/rider only after dependency/device approval. Token removal must be serialized with migration/refresh; no plaintext fallback or downgrading secrets. |
| Browser credential architecture | PARTIAL, decision pending | Current clients use localStorage bearer tokens, not cookie sessions. A full cookie/BFF redesign is not the smallest fix and has CORS/CSRF/client compatibility effects. Start with generation fences, private-cache clearing, redaction and CSP/egress boundary evidence. |
| Refresh rotation/reuse and old sid | PARTIAL, policy pending | Atomic server rotation needed; define replay after lost response, family invalidation and legacy no-sid expiry transition without breaking valid clients. Not automatic account-wide revocation on every ambiguous retry. |
| Checkout request identity | VERIFIED narrowly, preserve | UUID order ID + audit fingerprint and claimed original cart protect commit. Exact POST replay before quote expiry; GET 404 alone doesn't prove “never committed.” Never create a new ID on uncertainty. |
| POS legacy compatibility | PARTIAL | Source capabilities advertise idempotent cash sales but requestId remains optional for older callers. Decide whether old clients are blocked, upgraded or separately reconciled; do not call unidentified retries safe. Online/offline tenders are unavailable, not secretly implemented. |
| Financial source of truth | PARTIAL | COD enabled; customer digital confirmation endpoints reject. Real digital payments remain unimplemented and deferred until authentic signed provider callbacks, amount/currency/event validation and reconciliation are approved. No Bloom/cache/network success authorizes paid state. |
| COD fee/discount ownership | PARTIAL, explicit owner policy required | Parent total can include platform fees/cart discount while child totals differ. Code collects revised single-shop amount and terminal parent collected amount, refund caps only collected children, deterministic allocation metadata and settlement deductions. Owner must approve what each rider collects, who bears fees/discount/refunds, pending-parent reconciliation and physical remittance. Existing tests are not a signed accounting policy. |
| Refund destination | PARTIAL | Current completed refunds credit an internal customer wallet once; not proof of a cash/bank refund provider or withdrawable wallet. Agree customer-facing terms and settlement handling before pilot. Never infer refund success from notification delivery. |
| Durable effects | MISSING outbox; proposed | Existing inbox rows and timer are not guaranteed business-event delivery. Prefer stable event identity tied to same domain transaction; optional providers outside transactions. Queue choice follows workload/operations constraints, not an automatic package installation. |
| Rate limiting storage | PARTIAL, decision pending | PostgreSQL already serializes recipient OTP limits. General budgets need per-family key dimensions/bursts and shared atomic state if replicas. In-memory provider gate is local only. Do not add Redis or new DB schema under Phase 0. |
| Trusted proxy / client IP | UNVERIFIED deployment topology | Direct DNS/Caddy topology is historically recorded, but exact trusted hops/headers not inspected now. Define trusted peers and sanitize spoofable headers before keying limiters. CORS is not an identity firewall. |
| Ordinary cache | PARTIAL | Shop has session-only success cache and invalidation; backend source has no response cache. Correct late-write/session/permission scoping first. Public keys include representation/query/pagination/location/category/sort; recommendations with actor context remain private. Checkout/payment/stock correctness always reads authoritative state. |
| Negative cache | NOT_NEEDED_YET | No measured authoritative missing-public-ID load provided. If later justified: short bounded TTL/capacity, authorized/public only, invalidate on creation/publication; never cache 401/403, actor-dependent 404, outages, empty area inventory or payment uncertainty as absence. |
| Bloom filter | NOT_NEEDED_YET / P3 | No measured miss-volume or DB-cost evidence justifies it. Reconsider after ordinary cache/query/index measurements show material residual cost, feasible bounded memory/false-positive target and synchronized rebuild/update path. A negative from cold/stale filter must fall through to authority. It must never authorize, reject stock/money/order creation or override true DB existence. |
| Database/index performance | UNVERIFIED runtime plans | Schema includes many indexes; current installed indexes/plans/cardinality/latency not inspected. Measure on synthetic/staging data before changing; preserve correct totals and best-offer selection, not a blanket cap that hides records. |
| Rider GPS | PARTIAL; foreground behavior retained | Focused active assigned delivery with permission, watcher stop and authVersion checks already exists. Background/terminated-app tracking is not an approved promise. Device/permission/network changes require test evidence; do not remove pickup/delivery to avoid evaluating privacy. |
| Theme/design policy | PARTIAL coverage, preserve | Existing customer/rider Light/Dark/System and web/shop/admin approved designs are authoritative; merchant native uses existing fixed theme. A missing theme mode is not permission to replace design. Test current behavior, fix only approved hardening-related usability. |
| Auto-deployment | PARTIAL, intentionally inactive | Preparation-only authorization must be preserved. No restricted account/env secrets/activation variable installed by this audit. Native/staging/final release and restore proof remain distinct gates. |
| Backup service targets | UNVERIFIED, owner decision | Agree RPO/RTO, encryption, offsite retention, restore owner and physical file recovery; dump/list/archive hashes don't demonstrate application restoration. Critical evidence work starts before Phase 5. |
| Audit runtime verification | NOT_NEEDED_YET for Phase 0 execution | Source parser and static reads are isolated; no application imports/build/test runs or production probes. Tests and exact environments proposed in TEST_EVIDENCE; approve them separately. |

Unresolved owner decisions are not silently resolved by a document or marked implemented. See [RELEASE_GATES.md](RELEASE_GATES.md).
