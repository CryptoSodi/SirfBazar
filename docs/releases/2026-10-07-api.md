# Latest API and WhatsApp integration

Pull **CryptoSodi/SirfBazar**, branch **master**, on the computer hosting the grocery API.
The backend directory is **apps/api**. GroceryServer/codex/full-grocery-workspace is the
older workspace snapshot and is not the production checkout.

This release combines the latest merchant API (including registration, recovery,
documents, permissions and browser push), customer checkout/cart/support fixes, POS
counter fixes, and the WhatsApp delivery integration. Existing production frontends
are retained. No database or remote API process is changed by this Git push.

## Update the other computer

From the existing SirfBazar repository, with a clean working tree:

```sh
git pull --ff-only origin master
cd apps/api
npm ci
npx prisma generate
npm run typecheck
npm run build
```

Keep the existing private environment file, DATABASE_URL and JWT_SECRET. Add these
server-only settings, with the actual key entered privately:

- OTP_PROVIDER: whatsapp
- WHATSAPP_API_BASE_URL: http://otp.sirfbazar.com
- WHATSAPP_API_KEY: the API_KEY from /etc/whatsapp-otp-api.env on Oracle

Do not copy .env.example over an existing production .env. No credentials were
included in this release. Production refuses mock OTP. Newly issued codes replace
the old SHA-256 challenges; request a fresh OTP after updating.

Before starting the updated API, back up the database and review the additive
upgrade at apps/api/prisma/upgrades/20261007-auth-and-web-push.sql. It adds User.cnic,
RefreshToken.role, and WebPushSubscription. It is safe to repeat for an otherwise
matching schema and does not drop tables or existing data. Apply on the hosting
computer only, after verifying DATABASE_URL points at the intended database:

```sh
npx prisma db execute --file prisma/upgrades/20261007-auth-and-web-push.sql --schema prisma/schema.prisma
npm run whatsapp:ready
```

Restart the existing API service/process using its normal supervisor so it reloads
the code and environment. A Git pull does not restart it. Keep the normal port,
database and Cloudflare tunnel settings.

WhatsApp must return ready:true before real OTP sending can work. The last check
returned ready:false; the key authenticated, but the WhatsApp session was not ready.
The readiness command sends no messages. See apps/api/WHATSAPP.md for the provider
contract, failure handling and custom-message service methods.

## Verification and remaining limits

Prisma client generation, TypeScript checking, mocked WhatsApp/auth tests and 17
customer/POS regression tests passed in the isolated release checkout. No live
accounts, messages, orders or database changes were made by these checks. The
additive SQL is supplied for operator review; it was not applied to a live database.

The existing dependency lockfile reports 39 npm audit findings (4 low, 13 moderate,
21 high, 1 critical). Dependency remediation remains separate work; this release
does not claim a clean security audit.
