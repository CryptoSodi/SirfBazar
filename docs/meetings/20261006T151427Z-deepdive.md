## External Signals — Researcher

- **Multer 2.0.2 matches published denial-of-service advisory ranges.** The API uses its upload parser. Upgrade to a currently patched compatible release and verify upload handling. [Official advisory](https://github.com/expressjs/multer/security/advisories/GHSA-535w-7cp7-47q4).
- **Next 14.2.18 is unsupported** and matches a Windows-server security advisory. Production applicability depends on hosting; production exposure was not confirmed. [Support policy](https://nextjs.org/support-policy), [official advisory](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36).
- All eight npm audits reported zero, contradicting applicable official advisory ranges. Do not treat those audit counts as security clearance. Avoid unrelated blanket upgrades.

## Internal Health — Architect and QA

Highest-priority findings:

1. **Payment authority:** a customer can confirm a pending payment without verified provider proof. Reproduced with fake dependencies.
2. **Secrets and tenant boundaries:** rider order lists expose delivery OTPs; a merchant can attach another merchant's order to a support ticket. Both reproduced in isolation. Deleted/revoked-account and production-auth configuration gaps also need correction.
3. **Inventory and money consistency:** invalid replacement retries inflated fixture stock; concurrent settlement creation duplicated fixture earnings. Refund and order-transition races were identified in source and need real database tests.
4. **Checkout integrity:** restricted-product rules are inconsistent; missing address coordinates bypass delivery-radius checks; placement is not bound to an atomic customer-accepted quote.
5. **Customer-web recovery:** concurrent first additions split guest baskets; an uncertain merge switches to the account basket without durable reconciliation; transient refresh failure removes credentials. All three reproduced. Uncertain order recovery also needs persistence.
6. **POS recovery:** a lost successful response can lead to a second cash sale because retries lack a stable sale identifier. Source-confirmed scenario, not a real sale test.
7. **Accessibility:** browser testing confirmed invisible search keyboard focus and sign-in Tab navigation that skips terms/privacy links. The better-interface review therefore blocks that inspected flow; other UI surfaces remain unverified.
8. **Release coverage:** CI covers only API, customer web, and admin. Rider installed dependencies differ from its lockfile. Merchant search can show stale results; rider push-token refresh needs improvement. Live rider GPS is explicitly absent in this build, not a verified accidental regression.
