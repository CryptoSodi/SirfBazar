## Backend contracts

**Shared boundary.** Add a transaction helper with serializable isolation and three bounded, jittered retries only for serialization/deadlock conflicts. Domain helpers accept `Prisma.TransactionClient`; nested helpers never start independent transactions. Lock merchants in ID order for settlement-affecting mutations, then payment anchors before children/orders; every competing writer uses this order. Use conditional writes and bounded integer paisa, including intermediate sums. All financial/admin audits commit inside the transaction. Notifications/realtime run after commit; delivery failure is logged and cannot turn a committed operation into an HTTP failure.

Extend OrderStatusService with a transaction-aware expected-state transition; retain its ordinary wrapper. State, timeline, parent rollup, stock release and cancellation refund commit together. Only the winner of `{id,status:expected}` may restore stock. Migrate customer/admin cancellation, merchant rejection/timeout, payment failure and rider actions; prohibit terminal-to-active overrides that reserve/restock twice. Replacement reservation, original-item release, acceptance/rejection, totals and item state share this boundary. Preserve existing checkout conditional stock decrement. Recheck product approval/restrictions/availability, merchant approval/open/online state, owned finite/range-valid destination coordinates/service radius, coupon eligibility and quantities inside commit.

**Money.** Production customer confirm/fail/initiate mock routes fail closed; references from customers cannot establish paid state. Any retained simulation requires non-production AND an explicit test flag. Reject non-COD new marketplace orders. Refund create/approve/process checks collected value and ownership; unpaid COD cancellation never credits wallet. Lock payment anchor; cap completed plus reserved approved/processing refunds across parent/children against collected anchor value and affected child value. Claim eligible refund state conditionally, then wallet credit, refund/payment/order status and audit commit together. Repeated processing returns completed result without crediting twice; partial refunds remain partial.

Normalize new parent refunds into explicit child allocations in one transaction and persist allocation evidence in existing AuditLog JSON strings. Never count parent and child amounts twice. Include legacy parent refunds once with documented deterministic allocation; ambiguous historical amounts require reconciliation. Settlement generation reads/claims eligible ONLINE delivered orders inside its transaction with `settlementId:null`, then calculates only from claimed rows. No empty/negative payable batch can be paid. Refunds affecting pending settlements recompute and hold the batch atomically. Already-paid settlements return a reconciliation-required conflict before refund credit; an adjustment ledger is outside scope. Mark-paid claims PENDING only, verifies current deductions and writes reference/audit. Concurrent hold/pay cannot overwrite each other.

**Approved checkout v1.** Add authenticated `POST /orders/quote` in existing OrdersController. Input `{cartId,deliveryAddressId,paymentMethod:'COD',couponCode?}`; output `{version:1,approvedQuote,expiresAt,quote}`. Quote contains normalized merchant/item identities, quantities, unit prices, destination snapshot, fees, coupon/discount and total. Token signs a canonical digest with customer identity and five-minute expiry, using domain-separated HMAC from existing configured secret. Do not expose address PII in the token or trust a client digest. Reuse current module/configuration wiring.

New `POST /orders` requires UUIDv4 `requestId`, `cartId`, `approvedQuote` and existing address/method/note/coupon fields. Validate signature/customer/expiry, recompute inside placement transaction, then claim cart/create order/reserve stock. Missing token: `409 {code:'QUOTE_REQUIRED',message}`. Expired/changed quote: `409 {code:'QUOTE_CHANGED',message,quote?,approvedQuote?,expiresAt?}`; replacement data only when still eligible. Neither writes an order. Clients display changed details and demand fresh explicit approval.

Owned existing `Order.id=requestId` recovery runs BEFORE expiry, consumed-cart or changed-address checks. Compare immutable request fingerprint, stored with cart ID in transactional `CHECKOUT_CREATED` AuditLog metadata (existing POS pattern). Cross-owner/channel and changed-payload reuse conflict. Preserve legacy already-created order recovery checks. Older clients retain browsing/history/recovery but new unquoted purchases receive actionable update/review requirements: no optional bypass. Update both web and customer mobile checkout, smoke fixtures and API docs together. Shop/POS retain their sale-price review contract. Admin/merchant/rider clients consume safe status projections. A later coordinated release must make compatible clients available before enforcing this contract; this run does not deploy.

**Account/tenant boundaries.** JwtAuthGuard checks current account state and role membership on protected requests. AccessService checks active staff permissions and rider assignment; refresh/realtime entry points enforce equivalent current state. Explicit safe order projections cover lists/details/children/mutations/events; only owning customers see delivery OTP in existing reveal states. Support linked orders enforce customer ownership, merchant tenancy and rider assignment. Preserve WAHA delivery, expiry, retries and public browsing.

## Client and merchant contracts

**Recovery.** Web and standalone POS persist `{version,account/merchant/cashier identity,requestId,immutable payload,state}` before POST; failed storage write/readback blocks sending with recovery instructions. Timeout, lost response, 401, reload and uncertain conflict retain the record and show persistent reconciliation: GET same ID, then retry identical payload/ID. A 404 alone never authorizes a new ID. Only definitive no-write rejection permits a newly reviewed attempt. Pending recovery renders before empty consumed-cart UI. Other accounts cannot expose/replay its data. Native checkout extends existing persistence with approvedQuote; merchant iPOS retains its pending-sale behavior. Keep POS expectedUnitPricePaisa and receipt fingerprint validation.

**Catalogue/import.** Full-page category/subcategory disclosures, selectable grid and selected-items editor reuse category tree/browse data. Parent selection includes descendants explicitly. Stack regions in reading order on narrow screens; retain count/review access. Native checkboxes and disclosure buttons; “Select visible products” only selects eligible visible rows. Already-listed rows are excluded. Selection and price/whole-stock edits survive filtering/pages; partial failure retains failed rows.

Extend merchant bulk DTO/controller/service with `POST /merchant/products/bulk-preview` and bulk-upload fields `{requestId,mode:'ADD_MISSING'|'UPDATE_EXISTING',items:[{rowId,productId?,name?,categoryId?,unit?,merchantSku?,pricePaisa,stockQuantity,expected?}],previewToken?}`. Preview returns match/new/conflict/skip and old/new values with signed snapshot token. Updates/new-product creation require preview; known-ID add-only selections can commit directly after validation. Missing mode defaults ADD_MISSING, never legacy overwrite. Preserve `{created,updated,failed}` and add `{skipped,rows:[{rowId,status,merchantProductId?,error?}]}`. Update mode requires confirmed old price/stock/version and conditional writes: intervening sale forces re-preview. Do not silently reactivate listings or overwrite global barcodes. Preserve SKU strings and only match unique barcode/catalogue identity. Require inventory permission and tenant scope; new products follow moderation.

Each row transaction includes Product/merchant listing and a deterministic existing AuditLog primary key derived from merchant/batch requestId/rowId, plus payload fingerprint/result. Duplicate insertion rolls back duplicate effects; same retry returns saved success, changed payload conflicts. Successful rows never reapply after partial/lost response. This uses existing schema without an import job system.

Drawer states: file/paste → editable header mapping → preview → explicit confirmation → row results. Default 2 MiB/1,000 rows and bounded cells. Real quoted CSV parsing handles BOM, CRLF/LF, commas, escaped quotes and embedded newlines. No invented official iPOS headers. Preserve leading zeros; parse decimal rupees without floating rounding; validate safe paisa, whole units, duplicates/ambiguity and required stock. Distinguish sale price/cost and stock quantity/value. Missing stock never becomes zero silently. Excel users save as CSV.

**OTP/toasts/keyboard.** Style `.signup-verification input` with existing base input surface/border/text/focus rules; preserve visible label, six digits, paste, autocomplete and resend. Routine IPos add/hold/save uses existing toast API; pending sales/storage/actionable errors stay persistent. Portal to active modal dialog, otherwise fullscreen element, otherwise body; update target on dialog/fullscreen changes. Stable polite live region, no scanner focus movement/reflow; actionable errors persist.

Two concrete current-source keyboard defects replace unavailable original-audit attribution: (1) POS `components/ui.tsx:35` Modal used for Register Charge/Receipt lacks dialog semantics, containment, Escape and restoration; close glyph needs a descriptive name. Verify Charge → cash → Complete/Cancel → trigger using native dialog or complete focus utility. (2) Web `OpenMapPicker.tsx:24-36` initializes `chosen=false`; `moveend` updates coordinates, but only `dragend`/GPS enables confirmation, so keyboard pan cannot confirm a new point. AddressForm:182 selects OpenMapPicker or Google MapPicker. Add explicit keyboard map-center selection and focus containment/restoration to both variants. OpenMapPicker already has Escape; Google MapPicker lacks it. Verify denied GPS → keyboard select → confirm → form and Escape return. Existing LoginSheet handling is not blindly rewritten.

Interface skills require rendered verification of loading/empty/error/success states, long strings, 320px reflow, 200% zoom, keyboard/screen reader, measured contrast, visible focus and reduced motion. This source design does not approve rendered UI.

**Lifecycle.** CatalogScreen increments generation before awaiting location; only latest query/location generation sets results/errors/loading. All native push registration captures authenticated identity/session generation. Server token transfer is transactional; logout/delete scopes token AND owner, so stale cleanup cannot remove new ownership. Reject delayed old-session registration after logout/account switch server-side; ignoring the response client-side is insufficient. Active rider route imports RiderDeliveryScreen: foreground watch only when focused/app-active on an assigned active delivery; stop on terminal/background/logout/unmount. Handle denied permission; server rejects foreign/terminal-order pings. No background tracking.

Browser journeys cover OTP/catalogue/import, both keyboard defects, normal/native/fallback fullscreen and dialogs.
