## Release blockers

- **Authoritative restricted/prescription enforcement is absent on the server.** Product-detail checks in the client prevent normal Add/increase for disallowed products but are bypassable and cannot establish production eligibility enforcement.
- **No atomic accepted-quote/version contract exists.** A client GET quote and subsequent POST order are separate operations; client review/fingerprints cannot guarantee that prices remain unchanged between them. Placement idempotency prevents duplicate logical orders, not repeated HTTP attempts or this pricing race. Server-side acceptance of an explicitly reviewed quote/version and approved concurrency evidence are required before this gate can close.

These release blockers are independent of successful exports, static checks, unit tests, and isolated-fixture UI evidence.

Remaining native acceptance work applies to every row: capture light and dark on the intended devices; compare the pack at the intended viewport/density; exercise actual safe areas, status/navigation bars, keyboard, back handling, scrolling, text scaling, screen reader, reduced motion, system appearance, and process relaunch. Separately approve any real customer-data mutation tests. Browser-rendered React Native Web captures cannot close these native gates.
